# CWE-352: Cross-Site Request Forgery (CSRF)

**Category**: CSRF
**Severity**: High

An attacker tricks an authenticated user's browser into making unintended
requests to a vulnerable application.

## The Problem

Browsers automatically attach cookies (including session cookies) to every
request to a domain. If a state-changing endpoint relies solely on cookies for
authentication, an attacker can craft a page that triggers requests on behalf of
the victim: transferring funds, changing emails, or deleting data without the
user's knowledge.

## Defense

**Require a request-specific token or header that the attacker's page cannot
supply.**

### Go

```go
// WRONG: state change with only cookie auth
func handleTransfer(w http.ResponseWriter, r *http.Request) {
    user := getUserFromSession(r)
    doTransfer(user, r.FormValue("amount"))
}

// RIGHT: validate CSRF token on state-changing requests
func handleTransfer(w http.ResponseWriter, r *http.Request) {
    if !csrf.ValidateToken(r) {
        http.Error(w, "forbidden", http.StatusForbidden)
        return
    }
    user := getUserFromSession(r)
    doTransfer(user, r.FormValue("amount"))
}
```

### Python

```python
# WRONG: no CSRF protection on POST
@app.route("/transfer", methods=["POST"])
def transfer():
    do_transfer(current_user, request.form["amount"])

# RIGHT: framework CSRF middleware enabled (Django example)
# settings.py: MIDDLEWARE includes 'django.middleware.csrf.CsrfViewMiddleware'
# Template: {% csrf_token %} in every form
# Flask: use Flask-WTF CSRFProtect(app)
```

### TypeScript

```typescript
// WRONG: cookie-authenticated API with no CSRF protection
app.post("/api/transfer", (req, res) => {
  doTransfer(req.session.user, req.body.amount)
})

// RIGHT: verify CSRF token or use SameSite cookies + custom header
app.post("/api/transfer", csrfProtection, (req, res) => {
  doTransfer(req.session.user, req.body.amount)
})
// OR: require a custom header (X-Requested-With) that preflight blocks cross-origin
```

## Key Rules

- Enable CSRF middleware in your framework; it exists in Django, Rails, Express
  (csurf/csrf-csrf), Gorilla, and others
- Set `SameSite=Lax` (minimum) on session cookies; this blocks most cross-origin
  form submissions
- For APIs: use `Authorization` headers (Bearer tokens) instead of cookies; CSRF
  only applies to cookie-based auth
- Never perform state changes on GET requests
- For AJAX: require a custom header (e.g., `X-Requested-With`); browsers enforce
  preflight on custom headers cross-origin
