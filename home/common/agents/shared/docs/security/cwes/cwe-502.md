# CWE-502: Deserialization of Untrusted Data

**Category**: Insecure Deserialization
**Severity**: Critical

Deserializing untrusted data can instantiate arbitrary objects, leading to
remote code execution.

## The Problem

Many serialization formats (Python pickle, Java ObjectInputStream, PHP
unserialize, YAML `!!python/object`) allow embedded type information. When
untrusted data is deserialized, attackers can construct payloads that
instantiate dangerous objects or trigger code execution during deserialization.

## Defense

**Never deserialize untrusted data with a format that supports arbitrary
types.** Use data-only formats.

### Go

Go's `encoding/json` and `encoding/gob` are generally safe; they deserialize
into predefined structs, not arbitrary types. The risk is lower but still
validate the data after unmarshaling.

```go
// Safe: JSON into known struct
var user User
json.Unmarshal(data, &user)
```

### Python

```python
# WRONG: pickle from untrusted source
data = pickle.loads(user_input)

# WRONG: yaml.load with arbitrary types
data = yaml.load(user_input, Loader=yaml.Loader)

# RIGHT: data-only formats
data = json.loads(user_input)
data = yaml.safe_load(user_input)
```

### TypeScript

JSON.parse is safe (data-only). The risk comes from libraries that reconstruct
class instances from JSON or custom deserialization hooks.

```typescript
// Safe: JSON.parse returns plain objects
const data = JSON.parse(userInput)

// Validate the shape after parsing
const parsed = schema.parse(data) // zod, etc.
```

## Key Rules

- Never use `pickle`, `marshal`, `ObjectInputStream`, or `unserialize` with
  untrusted data
- Use `yaml.safe_load`, never `yaml.load` with the default Loader
- Prefer JSON for data interchange; it has no type system to exploit
- Validate deserialized data against a schema before use
- If you must deserialize complex types, use an allowlist of permitted classes
