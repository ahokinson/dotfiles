# CWE-1333: Regular Expression Denial of Service (ReDoS)

**Category**: Denial of Service
**Severity**: High

Regular expressions with certain patterns cause catastrophic backtracking when
matched against crafted input, consuming CPU for minutes or hours on a single
string.

## The Problem

Regex engines using backtracking (most languages except Go and Rust) are vulnerable when patterns contain nested quantifiers (`(a+)+`), overlapping alternation (`(a|a)+`), or quantified groups with optional elements (`(a*b?)*`). An attacker supplying input that triggers worst-case backtracking can lock up a server thread or process.

## Defense

**Never use user-supplied regex patterns directly. Avoid nested quantifiers in
regex that process user input.**

### TypeScript

```typescript
// WRONG: nested quantifiers — catastrophic backtracking on "aaa...!" input
const emailPattern = /^([a-zA-Z0-9]+)*@example\.com$/
emailPattern.test(userInput) // exponential time

// WRONG: user-supplied regex
const pattern = new RegExp(userInput)

// RIGHT: linear-time pattern without nested quantifiers
const emailPattern = /^[a-zA-Z0-9]+@example\.com$/
emailPattern.test(userInput)

// RIGHT: use re2 for user-supplied patterns (linear-time guarantee)
import RE2 from "re2"
const pattern = new RE2(userInput) // safe — RE2 guarantees linear time
```

### Python

```python
# WRONG: nested quantifiers
pattern = re.compile(r"^(a+)+$")
pattern.match(user_input)  # exponential backtracking

# WRONG: user-supplied regex without protection
pattern = re.compile(user_input)

# RIGHT: set a timeout (Python 3.11+ re module doesn't support this natively;
# use google-re2 for user-supplied patterns)
import re2
pattern = re2.compile(user_input)  # linear-time guarantee

# RIGHT: if you must use re, escape user input used in patterns
safe_pattern = re.escape(user_input)
re.search(safe_pattern, text)  # literal match, no special regex behavior
```

## Key Rules

- Never compile user-supplied strings as regex; use `re2` (linear-time) or
  `re.escape()` (literal match)
- Avoid nested quantifiers (`(a+)+`, `(a*)*`, `(a|b)*a`) in patterns that process user input
- Test regex patterns against ReDoS checkers before deploying (e.g., `recheck`,
  `safe-regex`)
- Go's `regexp` package uses RE2 and is immune to ReDoS; no special precautions
  needed
- Set request timeouts as a defense-in-depth measure; a locked regex should not
  lock the server indefinitely
