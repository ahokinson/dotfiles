# CWE-190: Integer Overflow

**Category**: Numeric
**Severity**: High

Arithmetic on fixed-width integers that exceeds the type's range wraps around or
truncates, leading to logic errors, buffer overflows, or security bypasses.

## The Problem

When an integer operation produces a value outside the representable range, the
result wraps (unsigned) or is undefined behavior (signed C/C++). This causes
incorrect size calculations, buffer allocations that are too small, and security
checks that pass when they should fail.

## Defense

**Validate ranges before arithmetic and narrowing conversions. Use
language-appropriate safe arithmetic.**

### Go

```go
// WRONG: unchecked conversion from int64 to int32
func allocateBuffer(size int64) []byte {
    return make([]byte, int32(size)) // silently truncates if size > MaxInt32
}

// RIGHT: validate before narrowing
func allocateBuffer(size int64) ([]byte, error) {
    if size <= 0 || size > math.MaxInt32 {
        return nil, fmt.Errorf("size %d out of valid range", size)
    }
    return make([]byte, int(size)), nil
}
```

```go
// WRONG: unchecked addition
total := a + b // wraps silently if both are large

// RIGHT: check for overflow before operating
if a > math.MaxInt64-b {
    return 0, errors.New("integer overflow")
}
total := a + b
```

### Python

```python
# Python ints have arbitrary precision — they do not overflow.
# However, overflow risks exist at boundaries with fixed-width systems:

# WRONG: trusting Python int when writing to a database int column
cursor.execute("INSERT INTO t (count) VALUES (%s)", (huge_python_int,))
# Fails or truncates if column is INT (max 2^31-1)

# RIGHT: validate against the target system's limits
MAX_INT32 = 2**31 - 1
if not (0 <= count <= MAX_INT32):
    raise ValueError(f"count {count} exceeds int32 range")
cursor.execute("INSERT INTO t (count) VALUES (%s)", (count,))

# WRONG: struct.pack without range check
struct.pack(">H", user_value)  # silently wraps if > 65535

# RIGHT: validate before packing
if not (0 <= user_value <= 0xFFFF):
    raise ValueError("value out of uint16 range")
struct.pack(">H", user_value)
```

### TypeScript

```typescript
// JavaScript numbers are IEEE 754 doubles — integers lose precision above 2^53

// WRONG: arithmetic on large external values
const total = Number(headerValue) + offset // loses precision above Number.MAX_SAFE_INTEGER

// RIGHT: validate integer safety
const value = Number(headerValue)
if (!Number.isSafeInteger(value)) {
  throw new Error("integer value exceeds safe range")
}
const total = value + offset

// For values that may exceed 2^53, use BigInt
const bigValue = BigInt(headerValue)
```

## Key Rules

- Go: validate ranges before narrowing conversions (`int64` to `int32`, `int` to
  `uint8`); check for overflow before addition/multiplication
- Python: ints don't overflow, but validate before writing to databases, binary
  protocols (`struct.pack`), or C extensions with fixed-width types
- TypeScript: use `Number.isSafeInteger()` for external input; use `BigInt` when
  values may exceed 2^53
- Never use unchecked user input as a size, length, offset, or index
- For cryptographic or financial calculations, use libraries designed for
  arbitrary precision
