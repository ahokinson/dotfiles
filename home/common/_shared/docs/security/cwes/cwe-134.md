# CWE-134: Format String Injection

**Category**: Injection
**Severity**: High

User-controlled input used as a format string allows reading from or writing to
memory, leaking sensitive data, or crashing the application.

## The Problem

When user input controls the format string itself (not just the values inserted
into a format), attackers can exploit format specifiers to access data they
shouldn't see. In Python, `str.format()` with user-controlled templates can
access object attributes and dictionary keys, leaking secrets from the
formatting context.

## Defense

**Never use user input as the format string. User input is data to insert, never
the template.**

### Python

```python
# WRONG: user controls the format template
message = user_template.format(user=current_user)
# Attacker sends: "{user.password}" or "{user.__class__.__mro__}"

# WRONG: user controls the format template via % operator
message = user_template % {"name": name}

# RIGHT: hardcode the template, user input is only data
message = f"Hello, {user_input}"

# RIGHT: if templates are truly needed, use a restricted formatter
from string import Template
# Template only supports $identifier and ${identifier} — no attribute access
message = Template("Hello, $name").safe_substitute(name=user_input)
```

### Go

```go
// WRONG: user controls format string
fmt.Fprintf(w, userInput, args...)

// RIGHT: user input is data, not the format string
fmt.Fprintf(w, "Result: %s", userInput)
```

## Key Rules

- User input is always a format *argument*, never the format *string*
- Python `str.format()` allows attribute access (`{0.__class__}`); never use it
  with user-controlled templates
- Use `string.Template` (Python) for user-customizable templates; it only
  supports simple substitution
- In Go, never pass user input as the first argument to `fmt.Sprintf`,
  `fmt.Fprintf`, etc.
- Log formatting: use structured logging (`slog.Info("msg", "key", value)`)
  rather than `fmt.Sprintf` with user data as the format string
