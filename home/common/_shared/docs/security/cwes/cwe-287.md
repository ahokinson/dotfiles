# CWE-287: Improper Authentication

**Category**: Authentication
**Severity**: Critical

Missing or flawed authentication allows attackers to access protected
functionality or data without proving identity.

## The Problem

When authentication checks are missing, bypassable, or improperly implemented,
attackers gain unauthorized access. Common mistakes: relying on client-side
checks, trusting user-supplied identity claims without verification, using
broken comparison logic, or failing to authenticate all protected endpoints.

## Defense

**Verify identity server-side on every protected request.** Never trust
client-supplied identity without cryptographic verification.

### Go

```go
// WRONG: trusting a header for identity
userID := r.Header.Get("X-User-ID")

// RIGHT: extract identity from verified JWT
claims, err := jwt.ValidateToken(r.Header.Get("Authorization"))
if err != nil {
    http.Error(w, "unauthorized", http.StatusUnauthorized)
    return
}
userID := claims.Subject
```

### Python

```python
# WRONG: trusting a cookie value as identity
user_id = request.cookies.get("user_id")

# RIGHT: validate session server-side
session = session_store.get(request.cookies.get("session_id"))
if session is None or session.is_expired():
    raise HTTPException(status_code=401)
user_id = session.user_id
```

### TypeScript

```typescript
// WRONG: trusting client-supplied user ID
const userId = req.headers["x-user-id"]

// RIGHT: verify token and extract identity
const claims = await verifyJWT(req.headers.authorization)
if (!claims) {
  return res.status(401).json({ error: "unauthorized" })
}
const userId = claims.sub
```

## Key Rules

- Authenticate on the server, never the client
- Use cryptographic verification (signed tokens, server-side sessions); never
  trust raw headers, cookies, or query params as identity
- Apply authentication middleware to all protected routes; use an allowlist for
  public endpoints, not a denylist for protected ones
- Use constant-time comparison for tokens and secrets to prevent timing attacks
- Enforce account lockout or rate limiting after repeated authentication
  failures
