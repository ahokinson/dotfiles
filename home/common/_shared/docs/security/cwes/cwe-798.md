# CWE-798: Hardcoded Credentials

**Category**: Credentials
**Severity**: Critical

Passwords, API keys, tokens, or other secrets embedded in source code.

## The Problem

Credentials in source code end up in version control, build artifacts, logs, and
error messages. They cannot be rotated without a code change and deploy. Anyone
with read access to the repo has the credentials.

This is unforgivable. There is no valid reason to hardcode secrets.

## Defense

**Use environment variables or a secret manager. Always.**

### Go

```go
// WRONG: hardcoded
apiKey := "sk-live-abc123" // gitleaks:allow

// RIGHT: environment variable
apiKey := os.Getenv("API_KEY")
if apiKey == "" {
    log.Fatal("API_KEY is required")
}
```

### Python

```python
# WRONG: hardcoded
api_key = "sk-live-abc123"  # gitleaks:allow

# RIGHT: environment variable
api_key = os.environ["API_KEY"]
```

### TypeScript

```typescript
// WRONG: hardcoded
const apiKey = "sk-live-abc123" // gitleaks:allow

// RIGHT: environment variable
const apiKey = process.env.API_KEY
if (!apiKey) throw new Error("API_KEY is required")
```

## Key Rules

- Never commit `.env` files; they must be in `.gitignore`
- Fail loudly on missing required credentials at startup, not at first use
- Use secret managers (Vault, AWS Secrets Manager, 1Password CLI) for production
- Rotate credentials immediately if they are ever committed; treat it as a
  breach
- Pre-commit hooks (e.g., `gitleaks`, `detect-secrets`) catch most accidental
  commits
- Connection strings with embedded passwords count as hardcoded credentials
