# CWE-1336: Server-Side Template Injection (SSTI)

**Category**: Injection
**Severity**: Critical

User-controlled input used as a template source allows arbitrary code execution
on the server through template engine features.

## The Problem

Template engines (Jinja2, Mako, Twig, EJS) are designed to execute expressions
within templates. When user input becomes the template itself (not just data
inserted into a template), attackers use template syntax to execute arbitrary
code. Jinja2's `{{ config.items() }}` leaks configuration; `{{
''.__class__.__mro__[1].__subclasses__() }}` leads to full RCE.

## Defense

**User input is template data, never template source. Never render
user-controlled strings as templates.**

### Python

```python
# WRONG: user input as Jinja2 template source
from jinja2 import Environment
env = Environment()
template = env.from_string(user_input)  # SSTI — user controls the template
result = template.render(data=data)

# WRONG: even with a "safe" sandbox, Jinja2 sandbox escapes exist
from jinja2.sandbox import SandboxedEnvironment
env = SandboxedEnvironment()
template = env.from_string(user_input)  # still exploitable

# RIGHT: user input is data, template is hardcoded
template = env.get_template("report.html")  # loaded from file
result = template.render(user_name=user_input)

# RIGHT: if user-customizable templates are required, use logic-less templates
from string import Template
result = Template("Hello, $name").safe_substitute(name=user_input)
```

```python
# WRONG: Mako template from user input
from mako.template import Template
result = Template(user_input).render()  # full Python execution

# RIGHT: template from file, user input as data
template = Template(filename="report.mako")
result = template.render(name=user_input)
```

## Key Rules

- User input is template *data*, never template *source*
- Load templates from files on disk, never from user-supplied strings
- If user-customizable formatting is needed, use logic-less template systems
  (`string.Template`, Mustache) that cannot execute code
- Jinja2's `SandboxedEnvironment` is not a reliable security boundary; sandbox
  escapes are regularly discovered
- Audit any code path where a string variable flows into `Template()`,
  `from_string()`, or `render_template_string()`
